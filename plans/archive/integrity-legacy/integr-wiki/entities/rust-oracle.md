# Rust Axum Oracle (Off-Chain Server)

The **Rust Axum Oracle** is the high-performance, off-chain verification and state ingestion server of the Integrity Project, functioning as critical infrastructure for the autonomous agent economy powered by smart contracts. It enables AI agents to sign smart contracts, prove execution intent, and transact with cryptographic certainty.

It is designed to handle high-volume telemetry ingestion from thousands of active AI agents, running complex cryptographic validations, pre-execution intent gating via Behavioral Commitment Chain (BCC) middleware, and mathematical scoring calculations in a zero-trust environment prior to on-chain settlement on Base L2.

## 1. High-Performance Architecture
To prevent CPU starvation and network congestion under institutional loads, the Oracle is engineered with asynchronous concurrency:
-   **Axum HTTP boundary:** A lightweight, non-blocking HTTP web server built in Rust that exposes fast, RESTful ingestion endpoints:
    *   `POST /v1/agent/register` - Registers new AI agent identities.
    *   `POST /v1/transactions/report` - Ingests telemetry, runs the off-chain Tri-Metric engine, and anchors state hashes.
    *   `POST /v1/transactions/verify` - Validates the cryptographic integrity of transaction logs.
    *   `POST /v1/disputes/raise` - Raises an optimistic challenge for consensus arbitration.
    *   `POST /v1/disputes/resolve` - Resolves disputes and invokes on-chain slashing.
    *   `GET /v1/agent/{identifier}` - Retrieves live composite metrics for the Explorer UI.
-   **PostgreSQL Trust Vault:** The persistent database of record that maintains transaction telemetry, DID parameters, and calculated AIS histories (seeded and managed via SQLx migrations).
-   **Authentication & TEE Attestation:** Validates hardware enclave measurements (Intel SGX/AMD SEV) for production hardware. For testing, developers use API Keys generated via the dashboard, which bypass strict hardware DID validation but cap their Trust Level (AIS) at a maximum of 300.

## 2. Cryptographic Labor
The Oracle operates under a strict **Zero-Trust** stance, performing exhaustive validations on every payload:
-   **Signature Verification:** Resolves the agent's W3C [did](../concepts/did.md), extracts the registered public key, and verifies the Ed25519 signature on the telemetry batch envelope.
-   **Noir Proof Verification:** Directly invokes Aztec Barretenberg native C++ FFI bindings to verify the mathematical [zkp](../concepts/zkp.md) proofs generated by the agent.
-   **State Compiling:** Computes rolling [Tri Metric Protocol](../concepts/tri-metric-protocol.md) scores and periodically submits the consolidated database Merkle root to `StateAnchor.sol` on Base L2.

## 3. Related Systems
-   **state-anchor:** Feeds verified state Merkle roots directly into the on-chain [State Anchor](state-anchor.md).
-   **integrity-registry:** Issues on-chain slashing triggers to the [Integrity Registry](integrity-registry.md) if compliance audits fail.
-   **Slasher:** Executes consensus slashing through [Slasher](../entities/smart-contracts.md) on Base Sepolia.
