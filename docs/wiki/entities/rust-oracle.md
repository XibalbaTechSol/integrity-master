# Rust Axum Oracle (Off-Chain Server)

The **Rust Axum Oracle** is the architecturally isolated, domain-agnostic **Layer 0** trust infrastructure of the Integrity Project. 

It is designed to handle high-volume telemetry ingestion from thousands of active AI agents across multiple vertical industries, running complex cryptographic validations and mathematical scoring calculations in a zero-trust environment.

## 1. High-Performance & Isolated Architecture
As of Phase 4, the Oracle has been isolated from industry-specific business logic, serving as a dedicated protocol enforcement layer:
-   **Multi-Tenant Isolation (domain_id):** Telemetry, transactions, and reputation state are partitioned by domain. This allows the Oracle to serve multiple independent frameworks (e.g. Shield, Quant) while maintaining strict data silo boundaries.
-   **Axum HTTP boundary:** A lightweight, non-blocking HTTP web server built in Rust that exposes fast, RESTful ingestion endpoints (such as `/v1/transactions/report` and `/v1/agent/register`).
-   **Scoring Abstraction Registry:** Supports dynamic scoring policies per domain. The Oracle fetches specific weights for Entropy, Grounding, and Sacrifice from a centralized registry, allowing for domain-optimized reputation calculation.
-   **PostgreSQL Trust Vault:** The persistent database of record that maintains transaction telemetry, DID parameters, and calculated AIS histories.

## 2. Cryptographic Labor
The Oracle operates under a strict **Zero-Trust** stance, performing exhaustive validations on every payload:
-   **Signature Verification:** Resolves the agent's W3C [did](../concepts/did.md), extracts the registered public key, and verifies the EIP-191 signature on the telemetry batch envelope.
-   **Noir Proof Verification:** Directly invokes Aztec Barretenberg native C++ FFI bindings to verify the mathematical [zkp](../concepts/zkp.md) proofs generated by the agent, avoiding the latency and memory overhead of WASM virtualization.
-   **State Compiling:** Computes rolling [Tri Metric Protocol](../concepts/tri-metric-protocol.md) scores and periodically submits the consolidated database Merkle root to `StateAnchor.sol` on Base L2.

## 3. Related Systems
-   **state-anchor:** Feeds verified state Merkle roots directly into the on-chain [State Anchor](state-anchor.md).
-   **integrity-registry:** Issues on-chain slashing triggers to the [Integrity Registry](integrity-registry.md) if compliance audits fail.
